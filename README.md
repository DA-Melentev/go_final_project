# Итоговое задание. Планировщик задач "Scheduler"

# Описание проекта
Приложение позволяет создавать задачи с привязкой к конкретным датам.
Для задач можно указать различные варианты повторения: 
- Через определенное количество дней
- Ежегодно
- По определенным дням недели
- В конкретные дни месяца (с возможностью указания месяцев)

Для работы с приложением достаточно открыть в браузере
`http://localhost:<порт>/`

- порт по умолчанию 7540. (Можно изменить задав переменную окружения `TODO_PORT`)

## Авторизация 
По умолчанию работа с приложением возможна без авторизации.
Для включения авторизации необходимо определить переменную окружения
`TODO_PASSWORD`. После определения этой переменной для работы с приложением понадобится 
указать пароль. Время жизни сессии - 8 часов.

## Структура проекта
- Директории `cmd`, `config`, `db`, `internal`, `migrations` - исходный код серверной части 
- В директории `tests` находятся тесты для проверки API
- Директория `web` содержит файлы фронтенда.

# Запуск
## Запуск локально
Для локального запуска приложения со значениями переменных по умолчанию достаточно
выполнить, находясь в корне проекта:

`go run cmd/server/main.go`

### Запуск с .env 

Содержимое .env файла расположено в конце readme.
Данный файл рекомендуется добавить в корень проекта.
Необходимые параметры можно раскомментировать и изменить.

Для запуска приложения с применением параметров из .env выполните

#### Linux, MacOS:
`env $(grep -v '^#' .env | xargs) go run cmd/server/main.go`

#### Windows (PowerShell):
```shell
Get-Content .env | Where-Object {
    $_ -notmatch '^\s*#' -and $_ -notmatch '^\s*$'
} | ForEach-Object {
    $key, $value = $_ -split '=', 2
    [System.Environment]::SetEnvironmentVariable($key.Trim(), $value.Trim(), 'Process')
}
go run cmd/server/main.go

```

Отдельные переменные окружения можно добавить вручную по формату, 
указанному в .env из примера. В таком случае запуск будет как в предыдущем пункте. 
___
## Запуск в Docker контейнере
Для звпуска приложения в Docker контейнере и сборки образа в проекте
присутствует Dockerfile

Для сборки выполните, находясь в корне проекта:

`docker build -t task-app:v1 .`

Для запуска контейнера, в случае, если используются 
значения по умолчанию выполните:

```shell
docker run -d \
  -v "<абсолютный путь к файлу базы данных на компьютере>:/scheduler.db" \
  -p <порт на компьютере>:7540 \
  --env-file .env \
  task-app:v1
```
*если .env файл не используется, строчку `--env-file .env \` можно исключить,


В случае, если порт приложения или путь к базе 
данных были изменены через переменные окружения, 
эти изменения нужно учесть при запуске приложения:
```shell
docker run -d \
  -v "<абсолютный путь к файлу базы данных на компьютере>:<абсолютный путь к базе данных в контейнере>" \  
  -p <порт на компьютере>:<порт в контейнере> \
  --env-file .env \
  task-app:v1                                         
```
*если .env файл не используется, строчку `--env-file .env \` можно исключить,

# Тестирование

Перед началом тестирования необходимо вручную пройти авторизацию на сервере.
После этого в логах бэкенда будет отображен сгенерированый токен.

`2025/01/09 03:39:16 New token generated: eyJhbGciOiJIU...8nS15JGo`

Данный токен необходимо вставить в переменную `Token` файла `tests/settings.go`

Необходимое содержимое файла `settings.go` с учетом выполненных заданий со звездочкой:
```go
package tests

var Port = 7540 //валидный порт бэкенда
var DBFile = "../scheduler.db"
var FullNextDate = true
var Search = true
var Token = ""//токен
```

Для запуска тестов выполните `go test ./tests`
